# ESP32 + MCP2517FD GVRET CAN FD адаптер

[English](README.md) | Русский

Прошивка для проверенной платы NodeMCU ESP-32S / классического ESP32-D0WD-V3 и
SPI-модуля CAN FD семейства MCP2517FD. Отдаёт в SavvyCAN **одну** шину CAN
через USB-последовательный порт на скорости **1 000 000 бод**. Текущий скетч
сообщает сборку 7.

Проект привязан к конкретному оборудованию и не является универсальным
профилем платы MCP2517FD. Кварц проверенного контроллера — **20 МГц**; SPI
ограничен **4 МГц**. Настройка CAN по умолчанию: 500 кбит/с в фазе арбитража
и 2 Мбит/с в фазе данных FD.

## Подключение

| GPIO / питание ESP32 | Метка на модуле MCP2517FD | Назначение |
|---|---|---|
| GPIO18 | SCK | Тактирование SPI |
| GPIO23 | SDI | SPI MOSI, ESP → модуль |
| GPIO19 | SDO | SPI MISO, модуль → ESP |
| GPIO5 | nCS | Выбор микросхемы SPI |
| GPIO21 | INT | Прерывание |
| GND | GND | Общая земля сигналов и питания |
| Стабилизированные 3,3 В | 3V3 | Логика 3,3 В — сверьтесь со схемой вашего модуля |
| Стабилизированные 5 В | 5V | Трансивер 5 В — сверьтесь со схемой вашего модуля |

По документации проверенного модуля нужны **оба питания, 5 В и 3,3 В, при
ведущем устройстве на 3,3 В**. В этой конфигурации не замыкайте перемычку P2:
вариант «только 5 В / P2» предназначен для ведущего устройства на 5 В. Перед
подачей питания проверьте свою плату — ревизии модулей могут отличаться.
Никогда не подключайте бортовые 12 В напрямую ни к одной из плат.
Используйте подходящий защищённый автомобильный источник питания и правильно
организованные трансивер и терминирование CAN. CAN-H и CAN-L подключаются к
сети CAN; таблица описывает только связь ESP с модулем.

Для первой проверки на столе питайте ESP от USB, а модуль — от проверенных
стабилизированных 5 В и 3,3 В с общей землёй. Не подавайте одновременно USB и
внешнее питание на VIN/5V ESP без проверенной схемы выбора источника. Стенду
CAN нужны два терминатора по 120 Ом, по одному на каждом конце шины.

## Сборка

Из корня репозитория, с Arduino CLI и ядром ESP32 Arduino:

```powershell
arduino-cli core install esp32:esp32@3.3.11
arduino-cli compile --fqbn esp32:esp32:nodemcu-32s --libraries .\libraries --build-path .\build\gvret .\firmware\esp32_mcp2517fd_gvret
```

В каталоге `libraries/ACAN2517FD` лежит точная копия библиотеки 2.1.16,
использованная для проверенной сборки. Её лицензия MIT и уведомление об
авторских правах Pierre Molinaro сохранены в
[`libraries/ACAN2517FD/LICENSE`](libraries/ACAN2517FD/LICENSE). Лицензия MIT
в корне репозитория распространяется на нашу прошивку и отладочные скрипты.
Сгенерированные файлы `build/` намеренно не хранятся в Git.

Прошивайте только точно опознанную плату. Для той же платы/FQBN:

```powershell
arduino-cli upload -p COM4 --fqbn esp32:esp32:nodemcu-32s --input-dir .\build\gvret
```

Замените `COM4` на ваш порт. Прошивка заменяет предыдущую программу.
Двоичные релизы этого репозитория, если они есть, рассчитаны на проверенный
профиль платы ESP32 с 4 МБ; объединённый образ перезаписывает флеш-память
целиком, включая сохранённые настройки.

## Протокол и поведение

- Приём и передача классического CAN и CAN FD (до 64 байт данных, с BRS).
- Стандартные и расширенные идентификаторы CAN, одна локальная шина
  (`bus 0`). SavvyCAN может присвоить ей другой **глобальный** номер шины.
- Классические кадры GVRET используют код операции `0x00`; расширение FD —
  `0x14`.
- По умолчанию прошивка работает в **обычном активном режиме** и при
  включённой шине может передавать кадры и выставлять ACK. Перед подключением
  к сети, где передача или ACK нежелательны, выберите Listen Only.
- Команды настройки и состояния FD — `0x15`–`0x17`. Режим с выключенным FD —
  Normal20B у MCP2517FD; включение FD возвращает NormalFD.
- Последовательное расширение FD проверено с изменённой сборкой SavvyCAN. Не
  рассчитывайте, что любая исходная или более старая сборка SavvyCAN понимает
  код FD `0x14`.

## Проверка и ограничения

Vector VN1640A использовался только как инструмент разработки и отладки,
чтобы проверить этот адаптер ESP32 на стенде. Он **не** входит в решение, не
является поддерживаемым оборудованием и не нужен для сборки, прошивки или
работы прошивки с SavvyCAN.

На изолированном стенде из двух узлов, где вторым узлом был канал CH1 Vector
VN1640A, 600 смешанных кадров ESP → второй узел (200 классических по 8 байт,
200 FD по 12 байт без BRS, 200 FD по 64 байта с BRS) приняты побайтно точно:
без потерь, дубликатов, ошибок на втором узле и ошибок TEC/REC у ESP, при
примерно 100 кадрах/с. Listen Only блокировал попытки передачи; режим с
выключенным FD блокировал передачу FD, а классический CAN продолжал работать.
Более ранние смешанные нагрузочные тесты второй узел → ESP и
двунаправленные тесты тоже пройдены. Отладочные скрипты Windows для этих
проверок лежат в `tools/` только для справки; им нужен отдельно установленный
драйвер Vector / XL API, файлов Vector в репозитории нет.

Это **не** сертификация для использования в автомобиле, устойчивости к
электрическим неисправностям или всех функций передачи SavvyCAN. Сначала
проверяйте на изолированном стенде с правильным терминированием. Никогда не
отправляйте диагностические или управляющие кадры в автомобиль, не понимая
устройство целевой сети и последствия.
